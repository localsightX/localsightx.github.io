How it works

Connect. Monitor. Act.

LocalSight runs AI on the low-res substream while recording the main stream — minimal compute, full fidelity. Every step on your hardware, encrypted and auditable.

  1. 1

    Connect your cameras

    Keep the hardware you own: RTSP / RTSPS / ONVIF from cameras and NVRs. TP-Link VIGI/Tapo NVRs provision in one call; ONVIF discovery and presets for Axis, Hanwha, Hikvision, Dahua, Reolink, Bosch cover the rest. No swaps, no cloud onboarding.

  2. 2

    AI starts monitoring

    Detection, tracking, behavior rules, ANPR and (opt-in) face matching run on the substream — no frames ever leave the server. GPU acceleration engages automatically when a model is staged.

  3. 3

    Get real-time alerts

    Matched events fan out to webhook / email / MQTT / push with storm-suppressing cooldowns, land in analytics, and become searchable on the unified timeline — signed clip export for evidence included.

  4. 4

    Own the whole stack

    Main-stream segments stay on your storage; snapshots, embeddings and plates are encrypted at rest. The code is MIT-licensed on GitHub — read it, audit it, change it. It's yours.

Privacy & compliance

Built so video stays yours

  • No cloud by default. All inference is local; the platform makes no outbound calls to third parties.
  • Recognition is opt-in. Face identification is disabled unless you explicitly enable it with a lawful basis.
  • Encrypted at rest. Stream URLs, embeddings, snapshots, plate data, alert configs, and MQTT credentials use envelope encryption (AES-256-GCM, per-record data keys).
  • SSRF guard. Camera, webhook, and ONVIF egress are blocked to private / loopback / metadata destinations unless allow-listed.
  • Per-route alert cooldown. Suppresses alert storms — one page per (channel × rule × camera) per window.
  • Immutable audit log. Every sensitive action — camera changes, alert routes, live-ticket issuance, video clip exports — is recorded.
  • Verifiable by design. The whole platform is open source — security claims don't have to be taken on faith, they can be read.
  • Bounded retention. A worker sweeper auto-expires recordings, events, snapshots, and embeddings on schedules you control.

Quick start

Running in minutes

LocalSight refuses to start if secrets are missing — there are no insecure defaults.

git clone https://github.com/jatinkray/localsight.git && cd localsight && python scripts/gen_env.py 
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python scripts/gen_env.py        # writes .env with fresh random secrets

uvicorn apps.api.main:app --host 0.0.0.0 --port 8000 --reload
# dashboard served at http://localhost:8000

# in another shell — runs cameras, recording, retention + alerts
python -m apps.worker
python scripts/gen_env.py
docker compose -f infrastructure/compose/docker-compose.yml --env-file .env up --build
# brings up PostgreSQL+pgvector, the API, the AI worker and an nginx TLS proxy

Recording and live view require FFmpeg on PATH (bundled in the Docker image). The default DB is SQLite; set DATABASE_URL for PostgreSQL.

Straight answers

Questions, answered honestly

No asterisks, no "contact sales". If something is a placeholder in the reference build, we say so.

Is it really free? What's the catch?

Yes — MIT license. No paid tiers, no per-camera fees, no feature gated behind a license key. The only costs are the hardware you already own and the electricity it draws.

Does it need the internet or send my video anywhere?

No. Inference, recording and alerts all run on your server. The platform makes zero third-party calls by default — no telemetry, no phone-home. Webhook/MQTT alerts go only to destinations you configure, and webhooks are SSRF-validated.

Can it run fully air-gapped?

Yes. Docker images and a local model registry mean a site with no outbound route at all works: detection, recording, live view, search and export are all LAN-only.

Do I need a GPU?

No. The CPU reference backend detects motion/person out of the box. For multi-class accuracy you stage an ONNX/TensorRT/OpenVINO model — GPU acceleration engages automatically when one is present.

Is face recognition enabled?

Face identification is off by default and opt-in, with enrollment data encrypted and retention-bounded. The privacy masks, RBAC and audit trail ship enabled instead — the safe posture is the default posture.

What hardware do I need to run it?

A mini-PC or any x86/ARM box with Docker runs the full stack; FFmpeg does the transcode work. AI load stays light because inference runs on the low-res substream while the main stream is only recorded.

Which cameras work?

Anything that speaks RTSP/RTSPS/ONVIF: TP-Link VIGI/Tapo NVRs provision in one call, plus presets for Axis, Hanwha, Hikvision, Dahua, Reolink, Bosch and GB/T 28181. See compatibility.

Can I trust what the AI actually detects?

The reference detectors are deterministic placeholders — functional for demos, honest about their limits. Production accuracy comes from staging your own model via the ModelRegistry; the pipeline, rules, alerts and evidence chain are production-ready today.
